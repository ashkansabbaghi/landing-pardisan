# هیئت پردیسان

شش صدای ثابت برای تصمیم‌های لندینگ مدرسه پردیسان. خروجی همیشه **فارسی** است.

با `pardisan-review`، `@pardisan-review`، «هیئت پردیسان»، «هیئت» یا «بررسی کامل» همین گردش کار اجرا می‌شود.

قبل از هر خروجی: [context.md](context.md) و [personas.md](personas.md) را بخوان. قبل از فایل ناظر: [report-template.md](report-template.md) را بخوان.

مخاطب تصمیم: **اشکان**.

## گردش کار

```
پیشرفت:
- [ ] ۱. تأیید موضوع (یا ۱–۳ سؤال شفاف‌ساز)
- [ ] ۲. شش متخصص مستقل و موازی
- [ ] ۳. ناظر بعد از هر شش
- [ ] ۴. نوشتن فایل Markdown
- [ ] ۵. خلاصه برای اشکان + مسیر فایل
```

### ۱. تأیید موضوع

موضوع را در یک یا دو جمله بازگو کن.

اگر موضوع ناقص است (هدف نامشخص، معلوم نیست ایده است یا تغییر کد یا تصمیم باینری): **قبل از هیئت** حداکثر ۱–۳ سؤال بپرس. هیئت را راه نینداز.

اگر کافی است، بدون مقدمهٔ طولانی برو سر گام ۲.

### ۲. شش متخصص — موازی و مستقل

بازاریابی، فنی، هزینه، ددلاین، مدیریت، تست **هم‌زمان** جواب می‌دهند. از روی هم کپی نمی‌کنند و پیش‌نویس یکدیگر را نمی‌بینند.

اگر ساب‌ایجنت سفارشی در `.cursor/agents/` در دسترس است، در **یک پیام** همین شش تا را صدا بزن:

- `marketing`
- `tech`
- `cost`
- `deadline`
- `management`
- `test`

به هر کدام فقط بده: موضوع، [context.md](context.md)، و **فقط** بخش نقش خودش از [personas.md](personas.md).

اگر ساب‌ایجنت سفارشی در ابزار Task نیست: شش `generalPurpose` موازی با همان محدودیت، یا شش جواب جدا بدون آشتی دادن.

هر جواب باید این چهار بخش را داشته باشد (همین عناوین):

- نظر از دیدگاه شخصیت
- پیشنهاد مشخص (قابل اجرا)
- ریسک‌ها از لنز همان نقش
- رای: موافق / مشروط / مخالف + یک جمله دلیل

رای فقط یکی از: **موافق** | **مشروط** | **مخالف**.

پیشنهاد باید عملی باشد (چه کار، کدام صفحه/فایل، چه مرزی) — نه شعار.

### ۳. ناظر — فقط بعد از شش جواب

ناظر هر شش را می‌خواند، بعد می‌نویسد:

- مقایسه صریح (توافق، اختلاف، نقطهٔ کور)
- رتبه‌بندی پیشنهادها
- رد / قبول هر پیشنهاد
- رای مستقل
- اگر تعارض تصمیم‌ساز است: **سوال از اشکان**
- یک فایل Markdown کامل

ناظر تملق نمی‌کند. اگر هر شش خوش‌بین‌اند و کسی هزینه یا تست را نگفته، می‌گوید.

**تعارض:** برنده را خاموش انتخاب نکن. سؤال دقیق بگذار. در توصیهٔ نهایی جمع‌بندی را **مشروط** بنویس.

### ۴. فایل گزارش

مسیر: `docs/reviews/` نسبت به ریشهٔ workspace (اگر نیست بساز).

نام: `docs/reviews/YYYY-MM-DD-<topic-slug>.md`

قالب: [report-template.md](report-template.md). عنوان بخش‌ها را عوض نکن.

کامیت نکن مگر اشکان بخواهد.

### ۵. خروجی در چت

برای اشکان، فارسی، کوتاه:

1. جدول آراء (شش متخصص + ناظر)
2. توصیهٔ ناظر و گام بعدی
3. سؤال‌ها اگر هست
4. مسیر فایل گزارش

متن کامل گزارش را در چت تکرار نکن.

## قواعد پایدار

- زبان: فارسی. لحن: فنی و اجرایی.
- اسم نقش‌ها را بیاور (بازاریابی، فنی، هزینه، ددلاین، مدیریت، تست)؛ به برچسب انگلیسی بسنده نکن.
- شش متخصص موازی؛ ناظر سری.
- تصمیم مبهم → سؤال از اشکان.
- این مهارت مخصوص لندینگ پردیسان است؛ هیئت شرکتِ کلی نساز.
- برای ادیت معمولی هیئت را راه نینداز؛ آن کار قاعدهٔ لنز روزمره است.
